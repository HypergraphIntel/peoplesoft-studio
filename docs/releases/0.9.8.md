# PeopleSoft Studio 0.9.8: Expanded PS Query and Integration Broker Change Review

**Draft — unreleased.** Initial preparation as of October 21, 2026. Package
metadata targets 0.9.8; no release date is set. The current published release
remains [0.9.7](0.9.7.md).

## PS Query authoring

On Oracle PeopleTools 8.62.09, Query authoring now includes:

- Standard, left outer and related-record joins.
- IN and correlated EXISTS subqueries, plus unions.
- Aggregates with HAVING and DISTINCT.
- Character/number expression columns and expression criterion operands.
- Long/short translates with current-date or field-date selection, and
  effective dating.
- WHERE criteria operators, prompts, number/date fields and typed operands.

The designer exposes record field catalogs, Add Record, aggregate and translate
properties, expressions, DISTINCT, and WHERE/HAVING tables. Migration carries
writer-validated Query shapes. MCP rename and delete are review-only: rename
stages an absent-target copy plus deletion of the old key, and does not rewrite
references. Destructive consent and normal Change Review application gates
remain required; fresh reviewed inverses restore complete query snapshots.

Installed acceptance found and corrected three designer defects: expression
submission read the form collection's length instead of the Length input;
result cells were blank for native projection names different from stored
field names; and unrelated subrecord placeholders made a record's direct
fields read-only. Result column names now accompany the native row objects,
including driver-disambiguated duplicate names. Subrecord fields are not
expanded.

Evidence includes 31 exact native Windows Query capture replays, native reopen
checks of Studio-written queries, and ten checks against an unmodified
installed candidate on VS Code 1.143.0 / HRDMO 8.62.09. The installed trial
checks editing, every displayed result cell, undo/redo/discard, staging without
writes, refusal without destructive consent, rename/delete and exact reviewed
undo. Temporary queries and deletion markers were removed and absence verified.
See [Query scope and installed acceptance](../PS_QUERY_WINDOWS.md) and the
[installed report](../../tools/lab/results/query-installed-2026-10-21.json).

Remaining Query limits include row-security SQL, nested subqueries, subqueries
combined with unions, effective-dated subquery/union records and HAVING OR.
8.61.15 authoring remains limited to one record, direct character fields and
one equal-to constant/prompt criterion until further HCDEV native calibration.

## Integration Broker review and lifecycle

Change Review now supports existing REST URI template text while preserving
ordered variables, mapping identity and the complete operation checkpoint.
Paired ApplicationClass REQUESTHDLR/OnRequest handler removal on 8.62.09 uses
the native deletion marker and supports typed inverse/redo.

On Oracle PeopleTools 8.62.09, bounded standard and REST service/operation
creation and deletion use complete definition checkpoints, dependency and
reference checks, native tombstones, rollback previews and verified readback.
Operation approval also binds the existing parent service's policy and state.
REST operation checkpoints include the writer-generated routing; recreation
may generate a new routing name, with logical equivalence verified.

Installed acceptance covers standard and REST definition deletion/recreation,
undo/redo of the previously added REST provider handler, existing-version
structural apply/inverse on 8.61.15, and REST consumer structural apply/inverse.
Recovery after a lost postcommit readback reconciles the complete live
after-image without replaying the write. See
[IB contracts and acceptance](../change-review/IB_STRUCTURE.md) and the
[progress evidence](../change-review/PROGRESS.md).

These are bounded metadata trials. Credentials, manual routings, URI message
bindings, broader child operations, 8.61 lifecycle/child deletion and other IB
definition families remain outside this scope. Runtime invocation is not
established by these metadata checks.

## App Engine Run and Monitor development

The source now includes a separate Run and Monitor workflow: native operator
sign-in, existing process/run-control choices, exact five-minute confirmation,
one native submission attempt, durable uncertain-outcome recovery, process and
distribution status, logs and output access. Entry points are available from
saved AE/Process Definition editors, Configuration Tools and Command Palette;
MCP submission always requires explicit developer confirmation.

Protocol, state/refusal, production HTTP and rendered Chromium fixture checks
pass. **A real installed submission and exact downloaded output are pending.**
The HRDMO public HTTPS gateway rejects native requests because the proxy's
backend hop is HTTP. A narrow verified-TLS proxy patch is prepared and has not
been deployed. This is development work, not accepted runtime capability or a
release. Local implementation, verification and candidate packaging are closed
out; the developer deferred the gateway prerequisite and remaining native
acceptance as **Low priority** (RT-L1 through RT-L4). See
[scope, evidence and remaining work](../PROCESS_SCHEDULER_RUNTIME.md).

## Core qualification fixes

- Fixed Windows Change Review persistence failing with `EPERM` while flushing
  a directory handle. Complete files are still flushed before atomic rename;
  directory flushing remains enabled on platforms that support it. The runtime
  preview history uses the same portable persistence rule.
- Included the SQL grammar declared by the extension, restoring installed SQL
  highlighting and checking contributed language paths during activation smoke.

- Windows local history replacement now retries bounded sharing/scan conflicts
  on the same temporary file. It retains the prior checkpoint on failure and
  never replays a PeopleSoft writer. Change Review, runtime preview and Build
  Request local metadata use the same replacement rule.

- SQL now has its own language configuration, including SQL line comments.
  Fixed malformed JSON and unsupported inline regex flags in the PeopleCode
  editor configuration. Smoke validates every contributed configuration and
  regex; compiler/encoder behavior is unchanged.
