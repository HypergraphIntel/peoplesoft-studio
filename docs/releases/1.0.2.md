# PeopleSoft Studio 1.0.2

Release date: November 24, 2026. Install it over 1.0.1, 1.0.0 or 0.9.x in
the same VS Code profile and reload. Nothing needs migrating; the
[upgrade notes](1.0/UPGRADE.md) still apply from 0.9.x.

1.0.2 is a patch release of the 1.0 core. The
[support contract](../SUPPORT_MATRIX.md) is unchanged: the qualified core is
still Oracle / PeopleTools 8.62.09, and other releases remain preview.

## PeopleTools 8.63

- **8.63 has a compiler profile (PT863).** On an 8.63 database Settings
  showed "No compiler profile", and Studio refused to validate, format or save
  PeopleCode. An 8.63 connection now selects PT863 automatically.
- **How it was checked.** Studio does not add a release profile on trust.
  The lab database was upgraded to 8.63.05, and the upgrade recompiled 963
  programs. Studio's compiler, run on the same source, now reproduces all 963
  byte for byte, with the same PSPCMNAME reference rows. No difference
  depended on the release, so PT863 models the same behavior as 8.61 and
  8.62. The evidence is in [Compiler profiles](../COMPILER_PROFILES.md#pt863-evidence-2026-11-24).

## PeopleCode compiler

Studio compiles PeopleCode itself when it saves. The first 8.63 check found
36 delivered programs it compiled differently from PeopleTools, or could not
compile. All 36 now match. The constructs involved occur in any recent
PeopleTools code, whatever the release:

- a comment inside an expression or argument list (`= /* note */ Value`,
  `<* ... *>` between `CreateArray` arguments);
- `Local boolean &b = (create X()).Method(...)`;
- `ComponentLife` variables of built-in types (`Rowset`) and of
  `%metadata:` classes;
- Function parameters and results of type `JavaObject`, `ProcessRequest`
  and `JsonBuilder`;
- the built-in types `IBConnectorInfo`, `Chart`, `CQRuntime`, `JsonParser`,
  `PTDirectTransferObject`, `CQChunkedProcessor` and `PPMClass`;
- a `"` inside a `REM` comment, which hid the Functions after it.

Programs that already compiled exactly are unchanged: the 30,134-program
8.61 reference corpus and the 8.62.09 lab sample show no regression.

## Connections

- **Update Password.** A database connection's password can be replaced
  without removing the connection: the **Update Password** button in
  Settings, *Update Password…* on the connection's menu in the Connections
  view, or the command palette. Studio tests the new password with a
  temporary connection and stores it only if the database accepts it; a live
  connection reopens with it. If the database can't be reached, you can save
  it without testing.
- **Expired passwords.** ORA-28001 (password expired) now counts as a
  credential failure, so Studio no longer keeps retrying the stored password.
