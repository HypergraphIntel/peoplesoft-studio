# PeopleSoft Studio 1.0.0

Release date: November 2, 2026. Install the 1.0.0 VSIX over 0.9.8 or 0.9.9 in
the same VS Code profile and reload; see [upgrade notes](1.0/UPGRADE.md).

## What 1.0 means

1.0 is the focused, dependable core defined in the
[release plan](../RELEASE_PLAN.md#10--dependable-core-workflows), not full
Application Designer parity. Its five gates, V1-1 to V1-5, passed on
October 22, 2026, for Oracle / PeopleTools 8.62.09 on Linux x64 and Windows
x64; the [qualification tracker](1.0/PROGRESS.md) records that evidence. The
[support contract](../SUPPORT_MATRIX.md) names the supported operations and
their limits, and it is unchanged by this release:

- **Stable core:** connect, open, edit, review, save and read back the
  supported definitions; reviewed undo and redo where Change Review covers the
  write; the declared Query and physical build workflows.
- **Bounded or preview:** Oracle / PeopleTools 8.61.15, and every workflow the
  contract labels preview. They keep their documented limits.
- **Not supported:** production SQL Server and DB2, and macOS clients. These
  are 2.0 candidates.

The 1.5 workflows delivered in [0.9.9](0.9.9.md) ship unchanged, outside the
core and with the limits listed there: structural Change Review, promotion
between Oracle environments, 8.61.15 Query parity, Run and Monitor and the
Windows AI handoff.

## New in 1.0.0

### Fluid pages and components through the MCP

`psft_page_create` takes `layoutPage` to create a Fluid page as App Designer's
New Page Fluid does: a copy of the Layout Page, then any further operations as
a second save. The new `set_fluid` page operation sets a control's Fluid tab.
`psft_component_create` and `psft_component_edit` take `fluid` for the
component's Fluid tab. Each of App Designer's 18 captured Fluid-tab saves
replays exactly. A content reference's own Fluid settings and a Fluid page's
style sheet are not covered yet.

### PeopleCode refused before the save, not after

Each rule below matches a program that passed Studio's checks, saved, and was
then refused by App Designer or failed at run time on a lab database:

| Rule | Refuses | Native result |
| --- | --- | --- |
| PC011 | A member call on a `create` expression | App Designer 2,47 |
| PC012 | A parameter named after a stored property | 2,31 Duplicate parameter name |
| PC013 | `%This.Prop = ...` for a readonly property | 2,46 property cannot be changed |
| PC014 | `Local integer &i, &n = 0;` | 2,42 |
| PC015 | `GetRow().ParentRow` | 2,52 |
| PC016 | A declared method with no body | Run time 2,81 (Validate Syntax accepts it) |
| PC017 | A string literal over 999 characters | App Designer and the application server crash on load |
| PC018 | `True`, `False` or `Null` after a dot | 2,49 |
| PC019 | An `array of integer` built from a number literal | Run time 180,604 (Validate Syntax accepts it) |
| PC020 | `%Request.Method` | 2,50 |
| PC021 | A value-returning `%This` method called as a statement on its own | 2,45 Invalid start of statement |

PC004 now also covers a Local named after a property, PC007 covers properties
of Application Class objects, and PC008 covers `SQLExec` outputs.
`psft_peoplecode_reference` lists every rule and adds guidance on reading one
row and on save events.

### Pages, components and records

- A push button added with a label shows its label: it is now saved as a Text
  button, not an Image button.
- A keyless Derived/Work search record is refused, with the alternative
  named: INSTALLATION as the search record, plus one invisible INSTALLATION
  field on the page.
- The "No data for scroll" check (App Designer 15,19) counts only table and
  view fields, as App Designer does. A grid filled by PeopleCode takes the new
  `set_scroll_use` operation over a Dynamic View.
- A grid column given a width keeps it in PIA. A grid added in the same
  operations can be given its occurs level.
- A class that `implements` an interface stores it in PROGEXTENDS, as App
  Designer 8.62.09 does.
- The record and field tools explain what `insert_field EFFDT` does, how a
  decimal Number's length is counted, and the 4-character limit on translate
  fields.

### Migration and validation

- Application Packages with owned subpackages now migrate, carrying each
  subpackage's owner ID. Subpackage descriptions and comments, and class
  descriptions, still refuse.
- App Engine validation checks `SQL.NAME` call sites against the SQL object
  again. The SQL text had been read as a LOB object, so no markers were seen.

### Studio Knowledge

New `file-layout` and `query` subsystems, with findings recorded from the File
Layout and Windows Query captures.

## Known limits

The [0.9.9 limits](0.9.9.md#known-limits) still apply, except that subpackage
owner IDs now migrate. Every limit and preview label in the
[support contract](../SUPPORT_MATRIX.md) stands. Not every write has Change
Review, and not every operation is reversible.
