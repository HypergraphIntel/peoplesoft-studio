# PeopleSoft Studio 1.0.1

Release date: November 11, 2026. Install it over 1.0.0, 0.9.9 or 0.9.8 in the
same VS Code profile and reload. Nothing needs migrating; the
[upgrade notes](1.0/UPGRADE.md) still apply from 0.9.x.

1.0.1 is a patch release of the 1.0 core. The
[support contract](../SUPPORT_MATRIX.md) is unchanged. The fixes come from the
MCP issue list in [PRIORITY_TASKS](../PRIORITY_TASKS.md), mostly found while
building applications through the MCP on the lab databases.

The 1.0.0 published on the Marketplace was built before the last 1.0 changes
were final. 1.0.1 is the first Marketplace build with all of them: rule PC021,
the PC004 extension to properties, array Locals, parameters and constants, and
the fixes listed below.

## Change Review and the MCP

- **A second record edit in one Change Set keeps the first (E22).** Two
  `psft_edit_record` calls on one record in a set used to build the second
  from the live record and silently drop the first. The second now builds on
  the staged proposal, and a field the first inserted can still be changed. A
  second `psft_edit_page` or `psft_ae_edit` on a staged object is refused
  rather than replacing it.
- **Lengths are checked before Oracle.** Page labels over 60 characters (E27,
  E40, E46, E55, E69, E78) and record default constants over 18 characters
  (E48) are refused with the limit, instead of failing in Oracle with
  ORA-12899.
- **Subpackages through the MCP, with undo (E11, E35, E52, E74).**
  `psft_create_package ROOT:Sub` or `ROOT:Sub:Sub2` creates one. With Change
  Review it stages, and undo removes it as App Designer's Delete and Save do.
  Captured on HRDMO: PBM and SYS move once per Delete, then the package is
  saved once, and no deletion marker is written. Apply a subpackage before
  staging the classes that go in it.
- **Web library PeopleCode keeps its license code (E37).** App Designer writes
  a `PSPCMPROG.LICENSE_CODE` on web library (`WEBLIB_`) programs. It is a
  fixed function of the record name: one value per record, the same after
  deleting and re-creating a program, and identical on HCDEV and HRDMO for
  all 158 programs licensed on both. Studio refused to update such programs.
  It now keeps the value on update, and gives a new program the value its
  record's other programs hold. The first program of a brand-new web library
  record still gets a blank value; it runs.
- **Unreproducible stored programs are refused at validation.** A PeopleCode
  change whose stored program the writer cannot reproduce used to pass
  validation and stop the set half-applied. Validation now runs the writer's
  check first.
- **Smaller fixes.** `set_use` refuses two key kinds in one change (E58).
  HTML and XSLT definitions can be named without their content type in every
  tool (E70, E60). New rule PC022 refuses a method or property named after a
  keyword (`Alias`, `Error`, `Doc`, and so on).

## Oracle Thick mode

`peoplesoft.oracle.clientMode` chooses Thin (the default) or Thick. Thick
loads Oracle Client libraries, which some databases need: Native Network
Encryption, older password verifiers, or a release before 12.1.

- **Instant Client directory.** `peoplesoft.oracle.thickModeLibDir` gives the
  directory. Empty means the system library search path. Setting a directory
  still selects Thick on its own, as before.
- **Oracle Net configuration.** `peoplesoft.oracle.configDir` names the
  `tnsnames.ora`, `sqlnet.ora` or wallet directory, in both modes.
- **One mode per window.** Starting Thick after a Thin connection, or with
  another directory, now asks you to reload the window.
- **Linux.** The Instant Client directory must also be on the library path
  when VS Code starts.
- **Which client is in use.** The connection tooltip and
  `psft_list_connections` name it.

Verified on HRDMO 8.62.09 with Instant Client 23.26: Thin and Thick returned
identical reads. See [Oracle Thick mode](../DATABASES.md#oracle-thick-mode).

## Known limits

- A class can't yet be staged into a subpackage created in the same Change
  Set (E47). Apply the subpackage first.
- The open MCP issues are listed in [PRIORITY_TASKS](../PRIORITY_TASKS.md)
  under "1.0.1 cycle goal".
