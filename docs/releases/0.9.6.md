# PeopleSoft Studio 0.9.6: Build, a PeopleCode language server and the AE/file workflow

Release date: October 20, 2026. Install the 0.9.6 VSIX and reload VS Code.
This release builds on [0.9.5](0.9.5.md).

## Build: Create Indexes, Alter Tables and Create Views

The record editor's **Build...** and **Build Project** now offer App Designer's
other build options on Oracle, beyond Create Tables. Every script matches the
one App Designer writes. Each was captured script-only on HRDMO 8.62.09, and the
captures are golden tests.

- **Create Indexes** keeps an existing index's physical clauses (from
  DBMS_METADATA). New indexes come from the DDL model. *Recreate index only
  if modified* compares the definition with the database.
- **Alter Tables** rebuilds by table rename, or adds columns in place, exactly
  as App Designer chooses. It honours the Build Settings for adds, changes,
  deletes, dropped columns that hold data, and shortened fields.
- **Create Views** resolves thirteen meta-SQL forms (%EffdtCheck, %Sql,
  %SubRec, %Table, %Concat, %DateIn, ...) as App Designer does. All 17 captured
  views reproduce, and about 97% of HRDMO's views can be built. A view with
  database-specific SQL now uses the connection platform's text instead of
  every variant run together.

Script lines are cut at a comma as well as at a space, as App Designer cuts
them. Cases without a capture are refused, with the reason. Studio's Alter
(both directions) and index rebuild ran natively on an empty lab table and
left nothing to change. See
[Build: indexes, views and Alter](../RECORD_SAVE.md#build-indexes-views-and-alter).

## PeopleCode editor

- **Problems as you type.** Validate PeopleCode runs half a second after
  typing stops. It compiles on a background thread, so even a 600 KB delivered
  application class never holds up the editor, and only the latest text
  counts.
- **Checked against the environment, as App Designer checks it.**
  - In Record and Component Record PeopleCode, a bare field name compiles as
    App Designer stores it: qualified with the program's record. A quick fix
    writes it that way before saving.
  - A name that is not a field, or a RECORD.FIELD the database does not have,
    is App Designer's "Field ... not defined. (2,17)".
  - A call that is neither declared nor one of 468 known built-ins is
    "Unknown function. (2,15)", as a warning that never blocks a save.
- **Settings > PeopleCode Editor** gathers the editor's options:
  - **Language Server**: switches completion, hover, signature help, Go to
    Definition, references, the outline and validation as you type on or off.
  - Validate as you type, and its delay.
  - The environment checks.
  - Unknown-function warnings.
  - The default PeopleCode decoder.

  Options that depend on a switch that is off are dimmed.
- **No-result call validation (PC010).** A call that returns nothing, used as
  a condition, assignment, operand or argument, is refused before saving.
  This covers 32 built-ins documented "Returns: None" and the void File
  methods on known Local File variables. No delivered HCDEV program is
  flagged.
- **MCP PeopleCode reads return the stored source** (App Designer's
  formatting). A read-modify-save no longer re-indents every line of a
  reviewed proposal.

## Requirements to a running App Engine

The synthetic request-to-runnable workflow for an AE that writes a file is
complete for its bounded scope. Coherent creation review covers new
Derived/Work records, App Engine programs and projects on Oracle:

- exact native rollback previews and precommit after-image checks;
- dependencies between proposed objects, validated before saving;
- new projects with explicit members, created in one native transaction.

Developer-approved HRDMO creation of four objects passed independent native
readback. The synthetic AE then ran natively as instance 607175, which
completed Success (report posting not verified) and wrote exactly the expected UTF-8 (no BOM) CSV.
Build Requests keep staged proposals and manual steps outstanding until they
are saved and read back. See
[AE/file workflow](../build-requests/AE_FILE_WORKFLOW.md).

## Change Review

- **Bounded Integration Broker structural review.** `psft_ib_save` stages
  these as proposals:
  - edits to an existing service's owner and namespace;
  - operation header, version, parameter and handler edits;
  - the calibrated OnRequest handler addition.

  Application must reproduce the writer's rollback preview exactly. Changes
  that reach routings keep the legacy per-write confirmation. Reversing an
  added handler is refused up front. Installed, developer-approved HRDMO
  application passed for a standard operation (restored by its typed inverse)
  and a REST provider handler addition. See
  [IB structure](../change-review/IB_STRUCTURE.md).
- **Native apply and typed inverse verified** on HRDMO for:
  - HTML, style sheet and Record PeopleCode;
  - Page, Component and Component Record Field PeopleCode, with redo;
  - Page redo;
  - a Query structural edit;
  - Query criteria and order.
- **Recovery.**
  - Reconciliation recognizes an unchanged baseline for an existing update,
    and can prepare a fresh reviewed continuation without replaying it.
  - Process saves no longer fail readback because of JSON key order.
- **Review page.**
  - Validating an empty Change Set is refused without marking it CONFLICTED.
  - The decided approach button stays in place, disabled.
  - Redo proposals are titled "Redo <original title>".
  - An unknown Change Set ID reports "Change Set not found".

## Validation and remaining scope

- Full verification: typecheck, bundle, 2,068 passing tests (one skipped),
  and activation smoke for 108 commands, 10 views and three custom editors.
- 54 production HTTP MCP/editor fixture checks on Node 20 and Node 26. CI is
  green on Node 20.
- PeopleCode compiler: 30,205 of 30,209 HCDEV programs compile exactly; the
  protected baseline holds at 430/430, with no regressions.
- Native HRDMO evidence as described above: Build captures and execution, IB
  structural and other adapter cycles, AE/file creation and runtime output.

Alter cases without a capture and Build on other platforms remain open, as do
definition-reference checks beyond records and fields, REST consumer and 8.61
structural review application, broader create/delete reversal, migration
apply, and representative production workflows. This release does not
establish complete Application Designer parity. Track the remaining
completion gates in [1.0 readiness](../RELEASE_1_0_READINESS.md).
