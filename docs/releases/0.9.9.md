# PeopleSoft Studio 0.9.9: Structural Change Review, environment promotion and 8.61 Query parity

Release date: October 23, 2026. Install the 0.9.9 VSIX and reload VS Code.
This release builds on [0.9.8](0.9.8.md) and delivers the
[1.5 targets](../RELEASE_PLAN.md#15--deeper-development-and-delivery-workflows)
V15-1 through V15-5. Each target passed native checks on the lab databases and
an installed developer session; the [1.5 tracker](1.5/PROGRESS.md) records the
evidence. The qualified 1.0 core and its [support contract](../SUPPORT_MATRIX.md)
are unchanged. The new workflows ship outside that core with the limits below.

## Structural Change Review (V15-1)

Larger reviewed edits now stage through Change Review with exact undo and redo:

- **Pages:** inserted and deleted controls, tab order and Edit Box rebinding
  (`set_binding`). Review records the ids the writer assigns. Undo restores
  deleted controls under their own ids and returns MAXPNLFLDID; redo restores
  the reviewed controls.
- **Records:** insert, remove and move fields and subrecords, plus Use, Edits,
  defaults and labels. A removed field returns from its own reviewed row.
  Removing a field still used by PeopleCode, pages, queries or other records
  is refused. DDL stays a separate build.
- **App Engine:** every `psft_ae_edit` operation stages the writer's full
  after-image. Undo reaches the checkpoint plus the deletion records App
  Designer writes for removed keys.
- **Application Packages and classes:** new classes and packages stage complete
  checkpoints. The new review-only `psft_delete_application_class` and
  `psft_delete_package` need destructive consent; undo re-creates the class
  with identical source, or the package with its subpackages and properties.

Installed acceptance (October 23, Linux VS Code, HRDMO 8.62.09): one Change Set
held a page, record and App Engine change. It was applied, inverted and redone
exactly; for example, a deleted control came back under its own id and
MAXPNLFLDID returned to 156. App Designer then reopened the page and gave its
next native control the following id. A class was created, deleted with
destructive consent and restored by undo, and App Designer opened it with the
same text.

A new class cannot be staged in the same Change Set as its new package: stage
the package first. The drift guard refuses an undo after App Designer edits the
same definition, as intended.

## Promotion between environments (V15-2)

**Promote Project to Another Environment…** and `psft_project_promote` export
a project, preview it against a different Oracle environment and stage the
import in that environment's Change Review. Packages record their source
environment. Migration now also carries alternate search keys, Oracle
In-Memory settings, message channels, process definitions, File Layouts and
App Engine step SQL members.

Verified HRDMO → HRDEV natively (prerequisites, conflicts, partial failure with
reconciled continuation, undo and redo). On the installed extension, a
13-definition business project was promoted through the UI; a fresh export
from HRDEV reads all 13 back unchanged with all 25 project members.
A separate promotion through `psft_project_promote` was applied and then undone,
leaving HRDEV as before.

Limits: a promotion that creates a process definition cannot be undone yet,
because process definition deletion is not calibrated. Subpackage and class
metadata are not migrated. Promotion is Oracle to Oracle only.

Fixed during acceptance: promotion lost its source connection when it
activated the target; Run and Monitor's background refresh re-activated
another connection mid-promotion; File Layouts could not be project members.

## Business request to running application, and Windows AI handoff (V15-3)

A representative benefits-eligibility Build Request (business requirements, a
file specification and a covering email) was analyzed by Claude Code and built
by Codex on Windows. The app combines records, a File Layout, an App Engine
program, a process definition, a page, a component, a menu and a project. It
ran through Run and Monitor, and its 1,821-row file matched the output of an
independent verifier. It was then promoted to HRDEV.

Windows fixes: Configure AI Client works with npm's `.cmd` launchers; handoff
arguments carry no quotes that PowerShell 5.1 would strip (Claude Code receives
its MCP configuration as a file); an analysis task no longer hides the build
task. App Engine validation now warns when SQL puts a subquery in an outer
join's ON condition, which Oracle rejects (ORA-01799).

## PS Query and PeopleCode editor (V15-4)

- **Every Query family on PeopleTools 8.61.15.** Criteria, number and date
  fields, prompts, joins, aggregates with HAVING and DISTINCT, expressions,
  subqueries, unions, translates and effective dating now save on 8.61.15 as
  on 8.62.09. Twelve queries built in 8.61.15 Windows Query match the rows
  Studio writes for the same design. Studio's writer accepted each design in a
  rolled-back preview there, and ran each Windows-made query.
  See [Query families on 8.61.15](../PS_QUERY_WINDOWS.md#query-families-on-86115-october-23).
- **New Query shapes (both releases):** row security as Windows Query
  generates it; Eff Date >=, <, > and First/Last Eff Date; HAVING with OR; Min
  and Max on date columns; WHERE criteria on expression columns (`#N`); nested
  subqueries and subqueries beside a union; between on date fields.
- **Format Document for PeopleCode** lays a program out as Application
  Designer does, reproducing App Designer's stored text for 30,114 of 30,208
  HCDEV programs. It applies only when the formatted text compiles to the same
  program.

## Run and Monitor native acceptance (V15-5)

App Engine Run and Monitor passed its native acceptance (RT-L1 to RT-L4) on
HRDMO with the installed extension. Each confirmed run created exactly one
process instance, reaching Success/Posted. Logs opened in the UI, and the
downloaded CSV matched its expected SHA-256. History survived a reload. A
double click, a stale run control, an expired confirmation, a read-only
connection and an unsaved editor were each refused, with no new instance.

Native rules found and encoded: the WS-Security header carries
`soap:mustUnderstand="1"` (without it PeopleSoft ignores the token); native
calls go one at a time (each handler re-enters the gateway, and parallel calls
deadlocked a two-PSAPPSRV domain); a completed Run Once run control is refused
at Review (PeopleSoft skips it yet reports Success).

Deployment note: in the lab, the gateway prerequisite was met by setting Req
Verification to None on the PROCESSREQUEST `PRCS_*` operations. The prepared
nginx TLS route was not needed. Operator sign-in still uses the operator's
password through WS-Security. Recovery from a lost response is covered by
fixture tests only. Scope remains Application Engine, existing run controls,
run now and WEB/TXT output. See [scope and evidence](../PROCESS_SCHEDULER_RUNTIME.md).

## Known limits

- Undo of a promotion that creates a process definition (above).
- Format Document keeps a lower-case built-in function name as typed, while
  App Designer stores `None(` for `none(`. Canonical built-in case is planned
  for 2.0 at low priority.
- A null test made in Windows Query keeps the blank or 0 constant its new
  criterion started with; Studio writes none. The SQL is the same.
- Between on number fields is not calibrated and is refused.
