# PeopleSoft Studio 0.9.7: Project migration with undo, PeopleCode completion and Approve and apply

Release date: October 21, 2026. Install the 0.9.7 VSIX and reload VS Code.
This release builds on [0.9.6](0.9.6.md).

## Project migration

Project migration now carries most of what a project holds, each type through
durable Change Review:

- **Fields** with every stored property (owner ID, IME mode, number/time
  formats, default century, custom format family) and their translate values.
  Export no longer refuses ordinary fields (New Field's default century of 50
  was read as an advanced property) and no longer drops owner IDs or
  non-character formats.
- **Records** with SubRecords, subrecord rows and SQL Table user-defined
  indexes.
- **Pages and components**, as complete native rows, created or replaced.
- **Application Packages** with their classes and root properties.
- **Standalone SQL**, HTML, freeform style sheets, standalone and associated
  Record PeopleCode, bounded PS Query and scoped standard/popup menus.

Each new writer follows a Windows App Designer capture and was compared row for
row with App Designer's own rows; definitions made by migration open and
re-save cleanly in App Designer. Preview shows the target baseline beside the
package payload; fingerprints are checked under lock before writing and
everything is read back after. Imports add only missing project members, so a
repeated import changes nothing.

Remaining refusals are explicit: alternate search keys, custom index DDL,
translations (PSXLATITEMLANG), subpackage/class metadata, nested and SQL Table
subrecords, and updates to indexed records or SubRecords. Native trials ran on
HRDMO 8.62.09 with export and import on the same lab database; cross-database
migration is not yet verified. See [project migration](../PROJECT_MIGRATION.md).

## Undo and redo of migrations and creations

An applied migration can be undone and redone from Change Review history,
including pages, components, fields, packages and classes, through deletion
writers calibrated against App Designer's File > Delete (captures dl01-dl13,
including recreating a deleted name). Creating Records, App Engine programs,
SQL, HTML, style sheets, Queries and projects can also be reversed.

Recovery covers interruptions: a crash or lost reply before or after a commit
reconciles without replaying the write, and an interrupted undo continues from
a freshly reviewed remaining-work proposal, with redo from the original
history. Native SIGKILL and lost-reply trials and installed VSIX checks passed
with full cleanup. See [recovery evidence and limits](../change-review/PROGRESS.md)
and [text deletion scope](../change-review/TEXT_DELETION.md).

Fixed along the way:

- Applying a review that creates a definition and something judged by it
  (Record PeopleCode under a new record) no longer stops with "Authorization
  context changed"; the changed ownership evidence is re-stamped and journaled
  after the live policy check.
- Applying a review that creates a definition and then saves more of it (a
  migrated field's properties, a package's subpackages) is no longer stopped by
  the delivered-object guard as "ownership or policy changed after Change
  Review".
- SQL text read through CLOB locators keeps supplementary Unicode characters
  at inline-fetch boundaries.

## Change Review: Approve and apply

**Approve and apply** is now the primary action for a validated proposal.
Approach approval is separate, and approval without applying stays under More
actions. Approval and application share one lock and bind the exact rendered
revision and eligible objects; rejected objects and their dependents stay
excluded, and a duplicate click cannot replay writes. Every existing gate
(approval hashes, the destructive checkbox, policy and dirty-editor checks,
native precommit checks, checkpoint and readback) remains. See
[design and verification](../change-review/APPROVE_AND_APPLY.md).

## AI write approvals and Build Requests

- **Write confirmations that time out end visibly.** AI Write Approvals shows
  pending cards and a status bar item; each request ends expired, cancelled,
  declined or approved, a late click never writes, and a retry gets a new ID.
- **Build Request progress accepts PENDING** for deferred work. The object
  stays outstanding and its history is kept.
- **Build handoff reaches the right window.** The Build button gives the
  configured Codex or Claude client a per-session MCP endpoint for the
  requesting Studio window. Both clients passed installed trials that read the
  approved spec, built through review and confirmation, and completed native
  runs with exact CSVs. See [handoff acceptance](../build-requests/BUILD_HANDOFF.md).

## Application Packages

Application Packages open in a tree workspace instead of the unsupported-text
message. Open or create a root, insert empty subpackages or classes, and open
class PeopleCode in its normal editor. Saves check the root version, policy and
scope, and are read back. See [package workflow](../APPLICATION_PACKAGES.md).

## PeopleCode editor

- **Completion knows every built-in function.** All 468 built-ins App Designer
  compiles are offered, in their stored casing.
- **RECORD.FIELD completion from the database.** After `JOB.`, completion
  offers JOB's fields, subrecords expanded.
- **`%This.` and `%Super.` complete the class's real members**, own and
  inherited (private ones for `%This.`), read when the class's editor opens.
  A base class named without its package resolves through the imports, as App
  Designer resolves it.
- **The suggestion list opens while you type.** PeopleCode editors turn off
  inline ghost-text suggestions by default, which kept the list closed in VS
  Code 1.141; `[psft-peoplecode]` settings override this.
- **Definition references are checked against the environment.** A
  `Record.X`, `Page.X`, `SQL.X`, `HTML.X` ... the database lacks is an
  Information note, since App Designer compiles them unchecked; `Image.X` gets
  App Designer's own warning. This also fixes 0.9.6 reporting `SQL.X` and
  `Page.X` as undefined fields.
- **Validation stays current.** Explicit validation runs on a background
  worker; slow completion reads are bounded and stale or cancelled results are
  dropped after edits, settings or connection changes, or closing the editor.

Editor acceptance: 13 checks against the unmodified installed VSIX on VS Code
1.141.0 / HRDMO 8.62.09 pass. See [editor acceptance](../PEOPLECODE_EDITOR.md).
